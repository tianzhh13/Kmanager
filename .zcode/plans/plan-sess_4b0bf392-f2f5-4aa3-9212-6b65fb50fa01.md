## 方案：消费组列表 lag 统一为 VictoriaMetrics 数据源

### 问题
TopicMonitor 的消费组列表 lag 来自 `getClusterMetrics`（即时查 Kafka），折线图 lag 来自 `kafka_consumergroup_lag`（查 VM），两个数据源不一致，展示值对不上。

### 方案
消费组列表的 `lag` 字段改为从 VM 的 `kafka_consumergroup_lag_sum` 指标聚合查询，和折线图的 `kafka_consumergroup_lag` 同源。`state`/`member_count` 仍保留即时数据（这些字段折线图不展示，不存在歧义）。

### 改动范围

#### 1. 后端：`batchQuery` 支持即时查询
**文件：** `internal/service/monitor/prometheus.go`

- `batchQueryItem` 结构体新增 `Instant bool` 字段（前端传 `true` 表示即时查询）
- `dedupedQuery` 结构体新增 `IsInstant bool` 字段
- 去重 key 加入 `instant` 前缀区分
- 查询时，`IsInstant` 为 true 的路由到 `QueryMetricsInstant` 而非 `QueryMetricsRange`
- 即时查询结果也写入缓存（key 带 `instant` 前缀，同样 30s TTL）

#### 2. 前端：`batchQuery` 类型定义新增 `instant` 字段
**文件：** `frontend/src/services/metrics.ts`

- `BatchQueryItem` 接口新增 `instant?: boolean` 可选字段

#### 3. 前端：TopicMonitor 消费组列表 lag 改为查 VM
**文件：** `frontend/src/pages/monitor/TopicMonitor.tsx`

- 新增 `loadConsumerGroupLags` 函数，在 `selectedTopic` 变化时调用
- 查询 VM：`sum(kafka_consumergroup_lag_sum{cluster_id="...", topic="..."}) by (consumergroup)` 即时查询
- 新增状态 `consumerGroupLags: Record<string, number>` 存储 `{group_id: lag}` 映射
- `consumerGroupRows` 的 `useMemo` 中，`lag` 字段优先取 `consumerGroupLags[group_id]`，没有则 fallback 到 `topicData?.lag`
- 加载时使用 `Spin` 提示

### 数据流
```
TopicMonitor.selectedTopic 变化
  --> loadConsumerGroupLags()
  --> POST /metrics/batch-query
      { id: 'cg_lags', query: 'sum(kafka_consumergroup_lag_sum{...}) by (consumergroup)', instant: true }
  --> 后端路由到 QueryMetricsInstant
  --> VM 返回即时聚合值
  --> setConsumerGroupLags({ group_a: 123, group_b: 456 })

consumerGroupRows 计算
  --> group_id / state / member_count 来自 metrics.consumer_groups（即时查 Kafka）
  --> lag 优先取 consumerGroupLags[group_id]（VM 数据）
  --> fallback 到 topicData?.lag（备选）
```

### 不变的部分
- 折线图 lag 数据源不变（`kafka_consumergroup_lag` range query）
- ClusterOverview TOTAL LAG 弹窗不变（仍用 `metrics.consumer_groups`）
- 其他所有功能不变
